## 0. 이 스킬이 존재하는 이유

프레임워크를 아는 것과 **언제 무엇을 쓸지 아는 것**은 다른 역량이다.

```
❌ 주니어:  프레임워크를 안다 → 전부 적용한다 → 분석은 두껍고 결론은 없다
✅ 시니어:  상황을 진단한다 → 문제 유형을 규정한다 → 도구 3개를 고른다 → 결론을 낸다
```

**Alex의 작업 순서는 항상 아래를 따른다. 이 순서를 건너뛰지 않는다.**

```
[1] 사업 특성 진단   무슨 사업이고 지금 어떤 상태인가        §1
[2] 문제 유형 규정   진짜 풀어야 할 문제는 무엇인가          §2
[3] 전략 유형 선택   어떤 종류의 답이 필요한가              §3
[4] 프레임워크 선택  그 답을 얻기 위한 도구 3~4개           §4
[5] 엔게이지먼트 실행 가설 → 검증 → 대안 → 권고             §5
```

> **§1~§3을 건너뛰고 §4부터 시작하면 반드시 "분석은 많은데 그래서 뭘 하라는 건지 모르겠다"는 결과가 나온다.**

## 1. 사업 특성 진단 — 7축 (작업 착수 즉시 수행)

Alex는 과제를 받으면 **가장 먼저 아래 7축을 판정하고 명시적으로 선언**한다.
정보가 부족하면 추측하지 말고 Graham에게 질문한다.

### 축 1. 사업 단계 (Stage)

| 단계 | 판별 기준 | 이 단계의 핵심 질문 |
|------|----------|-------------------|
| **아이디어** | 유료 고객 0 | 이 문제가 진짜인가 |
| **초기 (PMF 이전)** | 유료 고객 1~5, 이탈 발생 | 재구매·유지가 되는가 |
| **성장** | 유료 고객 6+, 반복 수주 | 어떻게 빠르게 늘리는가 |
| **성숙** | 매출 정체, 점유율 안정 | 어디서 새 성장을 얻는가 |
| **쇠퇴·전환** | 매출 감소, 마진 압박 | 무엇을 접고 무엇에 집중하는가 |

> 단계를 틀리면 처방 전체가 틀린다. **PMF 이전 기업에 GTM 확산 전략을 주는 것이 가장 흔한 오진이다.**

### 축 2. 수익 모델 유형

| 유형 | 특성 | 핵심 관리 지표 | 함정 |
|------|------|--------------|------|
| **판매형** (제품) | 1회성 거래 | 판매량, 마진율, 재고 | 반복 매출 없음 |
| **프로젝트형** (SI·용역) | 수주 기반 | 수주잔고, 가동률, 프로젝트 마진 | 인력 선형 확장, 스케일 안 됨 |
| **구독형** (SaaS) | 반복 매출 | MRR, Churn, NRR, LTV/CAC | 초기 적자 구간 길다 |
| **플랫폼형** | 양면 시장 | GMV, Take Rate, 양측 유동성 | 닭과 달걀 문제 |
| **라이선스형** | IP 사용료 | 계약 수, 로열티율 | 관계 유지 비용 과소평가 |

> **BESOLT 현재 = 프로젝트형 + 구독형 혼합.** 이 혼합 구조가 재무 해석을 왜곡하므로
> 사업계획 작성 시 **반드시 두 매출을 분리해서 제시**한다.

### 축 3. 고객 구조

| 구조 | 의사결정자 | 판매주기 | 설득 포인트 |
|------|----------|---------|-----------|
| B2C | 개인 | 즉시~수일 | 감성·편의·가격 |
| **B2B SME** | 대표 또는 임원 1인 | 1~3개월 | **ROI·구축속도·리스크 최소화** |
| B2B 대기업 | 다부서 합의 + 구매팀 | 6~18개월 | 안정성·레퍼런스·규정 준수 |
| B2G | 심사위원·평가 기준 | 공고 주기 | 정책 부합성·형식 완결성 |

> **B2B SME는 "대표 1명을 설득하면 끝"이지만, 그 1명이 실패를 두려워한다.**
> 따라서 SME 제안의 핵심은 화려한 비전이 아니라 **"실패해도 손실이 작다"는 구조 설계**다.

### 축 4. 시장 구조

| 구조 | 상황 | 전략 방향 |
|------|------|----------|
| **신규 창출** | 시장 자체가 없음 | 시장 교육 비용 발생, 초기 침투 느림 |
| **대체** | 기존 방식(엑셀·수작업·외주)을 대체 | **전환 비용 낮추기가 승부처** |
| **점유율 경쟁** | 동일 솔루션 다수 존재 | 차별화 또는 가격, 둘 중 하나 |
| **틈새** | 대형 벤더가 안 하는 영역 | 세그먼트 집중, 깊이로 방어 |

> **BESOLT의 실제 경쟁자는 대부분 "엑셀"이다.** 이것을 인정하지 않으면 포지셔닝이 틀어진다.

### 축 5. 경쟁 지위

| 지위 | 정의 | 정석 전략 |
|------|------|----------|
| 선도 | 1위, 점유율 최대 | 시장 확대, 표준 선점 |
| 도전 | 2~3위, 1위 추격 | 차별화 공격, 약점 집중 공략 |
| 추종 | 하위, 모방 | 원가 우위, 특정 채널 집중 |
| **틈새(니치)** | 세그먼트 1위 | **세분화 심화, 전환비용 구축** ← BESOLT |

### 축 6. 문제 유형 — **가장 중요한 축**

의뢰받은 과제가 실제로는 어떤 문제인지 규정한다. §2에서 상세히 다룬다.

### 축 7. 제약 조건

```
자본 제약   가용 예산, 자금 조달 가능성
인력 제약   투입 가능 인원, 필요 역량 보유 여부
시간 제약   마감(공고·계약·투자 라운드), 시장 진입 타이밍
규제 제약   인증·허가·법적 요건  ← 있으면 최상위 제약, 다른 모든 것에 우선
```

### 진단 결과 선언 형식 (작업 착수 시 필수 출력)

```markdown
## 사업 특성 진단
| 축 | 판정 | 근거 |
|----|------|------|
| 사업 단계 | 초기 (PMF 이전) | 유료 3사, 이탈 1건 발생 |
| 수익 모델 | 프로젝트형 + 구독형 혼합 | 구축비 70% / 구독 30% |
| 고객 구조 | B2B SME | 의사결정자 = 대표, 주기 2개월 |
| 시장 구조 | 대체 (vs 엑셀·수작업) | 신규 창출 아님 |
| 경쟁 지위 | 틈새 | SME 세그먼트 한정 |
| 문제 유형 | **PMF 검증 미완료** | 재구매 데이터 부재 |
| 제약 | 인력(영업 0.5명), 시간(공고 D-30) | |

→ **따라서 이 과제는 '확산 전략'이 아니라 'PMF 검증 설계'로 접근합니다.**
```

## 2. 문제 유형 규정 — 의뢰와 진짜 문제는 다르다

> 컨설턴트의 첫 번째 일은 **의뢰받은 질문이 옳은 질문인지 검증하는 것**이다.

### 2-1. 흔한 오진 패턴

| 의뢰받은 질문 | 실제 문제인 경우가 많음 | 잘못 답하면 |
|-------------|---------------------|-----------|
| "영업을 어떻게 늘릴까" | 제품이 아직 안 팔리는 상태 (PMF 미완) | 영업 인력만 늘리고 적자 확대 |
| "가격을 얼마로 할까" | 가치 제안이 불명확 | 가격 경쟁으로 마진 붕괴 |
| "신사업 뭘 할까" | 기존 사업 수익성 악화 회피 | 자원 분산, 양쪽 다 실패 |
| "투자를 받아야 할까" | 단위경제(Unit Economics) 미검증 | 적자 구조를 자본으로 연장 |
| "조직을 어떻게 짤까" | 전략 부재로 역할 정의 불가 | 조직개편 반복 |

**Alex의 대응**: 의뢰 질문에 바로 답하지 않고, 먼저 아래를 확인한다.
```
"이 문제를 해결하면 무엇이 달라집니까?"
"이 문제가 없었다면 지금 상황이 어떻게 다를까요?"
"이 문제를 지금까지 어떻게 해결해 오셨습니까? 왜 안 됐습니까?"
```

### 2-2. 문제 유형 6분류

| 유형 | 증상 | 진짜 원인 후보 |
|------|------|--------------|
| **A. 성장 정체** | 매출 횡보, 신규 고객 감소 | 시장 포화 / 세그먼트 소진 / 제품 노후 |
| **B. 수익성 악화** | 매출은 있으나 이익 감소 | 원가 상승 / 가격 하락 / 저마진 고객 비중 |
| **C. PMF 미완** | 고객은 있으나 유지 안 됨 | 가치 제안 불일치 / 타겟 오설정 |
| **D. 신규 진출** | 새 시장·제품 필요 | 기존 성장 한계 / 기회 포착 |
| **E. 자금 조달** | 현금 부족, 투자·대출 필요 | 성장 투자 / 운전자본 / 적자 보전 |
| **F. 실행·조직** | 전략은 있으나 안 굴러감 | 우선순위 부재 / 역량 부족 / 인센티브 불일치 |

**하나로 규정하기 어려우면 복합 문제이며, 이 경우 반드시 우선순위를 정한다.**
동시에 여러 문제를 다루면 어느 것도 해결되지 않는다.

## 3. 문제 유형 → 전략 유형 매핑

### 3-1. 매핑 테이블 — **Alex의 처방전**

| 문제 유형 | 1순위 전략 방향 | 2순위 | 하지 말아야 할 것 |
|----------|---------------|-------|----------------|
| **A. 성장 정체** | 세그먼트 확장 or 제품 확장 (Ansoff) | 채널 다각화 | 무조건 신사업 |
| **B. 수익성 악화** | 원가 구조 재설계, 고객 포트폴리오 정리 | 가격 재설정 | 매출 확대로 덮기 |
| **C. PMF 미완** | **타겟 재정의 + 가치제안 재설계** | 파일럿 재설계 | **영업·마케팅 투입 확대** |
| **D. 신규 진출** | 인접 시장 우선 (Ansoff 리스크 최소) | 파트너십 진입 | 다각화 직행 |
| **E. 자금 조달** | 단위경제 개선 후 조달 | 정책자금 우선 | 적자 구조로 투자 유치 |
| **F. 실행·조직** | 우선순위 3개로 압축, 게이트 도입 | 인센티브 정렬 | 조직도만 바꾸기 |

### 3-2. 사업 단계별 전략 원칙

```
아이디어      : 검증에 투자한다. 확장에 투자하지 않는다.
초기(PMF 전)  : 고객 수보다 재구매율. 1개 세그먼트에 집중.
성장          : 반복 가능한 획득 경로 확립. 이때부터 영업 확대.
성숙          : 인접 확장 + 원가 우위. 신사업은 여기서.
쇠퇴·전환     : 철수 기준 먼저 정하고, 남길 것에 집중.
```

> **가장 비싼 실수: 초기 단계에서 성장 단계 전략(영업 확대·마케팅 투입)을 쓰는 것.**
> PMF가 없는 상태의 영업 투자는 구멍 난 양동이에 물을 붓는 것과 같다.

### 3-3. 경쟁 지위별 전략 원칙

```
선도  : 시장 파이 자체를 키운다. 표준을 선점한다.
도전  : 1위의 강점이 아니라 1위가 못 하는 것을 공격한다.
추종  : 정면 승부 금지. 원가 또는 특정 채널.
틈새  : 세그먼트를 더 좁힌다. 깊이로 전환비용을 만든다.  ← BESOLT
```

## 4. 전략 유형 → 프레임워크 선택

> **규칙: 문서당 프레임워크 최대 4개.** (`business-ideation-and-analysis.md` §4와 동일)
> 여기서는 **어떤 4개를 고를 것인가**를 문제 유형 기준으로 규정한다.

### 4-1. 문제 유형별 프레임워크 처방

| 문제 유형 | 필수 프레임워크 | 보조 | 산출 형태 |
|----------|---------------|------|----------|
| **A. 성장 정체** | Ansoff, STP, 3C | BCG Matrix | 성장 옵션 3개 비교표 |
| **B. 수익성 악화** | Value Chain, 원가구조 분해, 고객수익성 분석 | Porter 5F | 원가 절감 시나리오 |
| **C. PMF 미완** | **VPC, JTBD, 3C(고객)** | Lean Canvas | 타겟 재정의 + 가치제안 재설계안 |
| **D. 신규 진출** | PESTEL, 3C, TAM/SAM/SOM, Ansoff | Porter 5F | 진입 타당성 + Kill Criteria |
| **E. 자금 조달** | Unit Economics, 3-Scenario P&L | TAM/SAM/SOM | 조달 구조 + 상환·회수 계획 |
| **F. 실행·조직** | OKR 계층화, RACI, 게이트 프로세스 | - | 우선순위 3개 + 실행 로드맵 |

### 4-2. 프레임워크 선택 3원칙

```
① 질문 대응 원칙
   각 프레임워크는 "답해야 할 질문 1개"에 대응되어야 한다.
   질문이 없는데 들어간 프레임워크는 제거한다.

② 중복 제거 원칙
   같은 질문에 답하는 프레임워크를 2개 쓰지 않는다.
   (예: 3C와 SWOT을 동시에 쓰면 자사 분석이 중복된다 → 하나만)

③ 결론 도달 원칙
   그 프레임워크를 채웠을 때 의사결정에 쓸 결론이 나오는가?
   나오지 않으면 그 프레임워크는 이 과제에 부적합하다.
```

### 4-3. 선택 근거 명시 의무

Alex는 프레임워크를 사용할 때 **왜 그것을 골랐는지 반드시 기술**한다.

```markdown
## 프레임워크 선택 근거
| 프레임워크 | 답하려는 질문 | 선택 사유 |
|----------|-------------|----------|
| VPC | 고객이 왜 안 사는가 | PMF 미완이 핵심 문제이므로 가치제안 정합성 검증이 우선 |
| JTBD | 고객은 무엇을 시키려 하는가 | 경쟁 대상이 엑셀이므로 '일' 관점 재정의 필요 |
| 3C(고객 중심) | 어느 세그먼트로 좁힐 것인가 | 타겟 재정의가 처방의 핵심 |

**미사용 사유**
- PESTEL: 거시 환경은 이번 문제(PMF)와 무관 → 제외
- Porter 5F: 산업 수익성이 아니라 개별 가치제안 문제 → 제외
- SWOT: 3C와 자사 분석 중복 → 제외
```

> **"쓰지 않은 이유"를 적는 것이 시니어와 주니어를 가른다.**
> 이것을 적으면 분석의 범위가 통제되고, Graham이 누락 여부를 판단할 수 있다.

## 5. 엔게이지먼트 실행 방법론

### 5-1. 5단계 프로세스

```
[1] 문제 정의       진짜 질문을 규정한다              §2
[2] 이슈 구조화     MECE 이슈트리로 분해한다
[3] 가설 수립·검증  Day 1 Answer → 팩트로 검증
[4] 대안 설계       최소 3개 옵션 + 비교
[5] 권고·실행계획   1개 권고 + 실행 로드맵 + Kill Criteria
```

### 5-2. 이슈트리 (Issue Tree) 작성법

핵심 질문을 MECE하게 분해하여, **답할 수 있는 크기**까지 쪼갠다.

```
핵심 질문: 왜 유료 고객이 유지되지 않는가?
├── 제품이 가치를 못 주는가?
│   ├── 약속한 기능이 작동 안 함        → 검증: 장애 이력, QA 리포트
│   ├── 기능은 되나 효과가 미미          → 검증: 고객사 개선 수치
│   └── 효과는 있으나 체감 안 됨         → 검증: 리포팅 방식 인터뷰
├── 고객이 잘못 선택되었는가?
│   ├── 문제 심각도가 낮은 고객          → 검증: 도입 전 Pain 강도
│   └── 예산·의사결정 권한 부재          → 검증: 계약 주체 분석
└── 운영·지원이 부족한가?
    ├── 온보딩 실패                     → 검증: 초기 30일 사용률
    └── 담당자 이탈 후 방치              → 검증: 사용자 로그 추이
```

**규칙**
- 각 가지는 **검증 방법**이 함께 적혀야 한다. 검증 불가한 가지는 이슈트리에 넣지 않는다.
- 깊이 3단계를 넘기지 않는다. 넘어가면 과잉 분해다.
- **80/20**: 전체 가지를 다 검증하지 않는다. 영향이 큰 2~3개만 검증한다.

### 5-3. Day 1 Answer (가설 우선)

> 자료를 다 모은 뒤 결론을 내지 않는다. **첫날에 가설 답을 세우고, 그것을 깨는 방향으로 검증한다.**

```markdown
## Day 1 가설
가설: "이탈 원인은 제품 성능이 아니라 온보딩 실패다."
근거(초기): 이탈 2건 모두 도입 후 30일 내 사용률 20% 미만
반증 조건: 온보딩 완료 고객에서도 이탈이 발생하면 이 가설은 틀림
검증 방법: 전체 고객 초기 30일 사용률 vs 유지 여부 교차 분석
소요: 2일
```

**가설이 틀리는 것은 실패가 아니다. 가설 없이 자료만 모으는 것이 실패다.**

### 5-4. 대안 설계 규칙

```
대안은 항상 3개 이상 제시한다. 단, 성격이 달라야 한다.
  ❌ 나쁜 예: A) 영업 2명 채용  B) 영업 3명 채용  C) 영업 4명 채용
  ✅ 좋은 예: A) 세그먼트 집중  B) 파트너 채널  C) 제품 단순화 후 셀프서비스

각 대안에 반드시 포함:
  - 필요 자원 (인력·예산·기간)
  - 기대 효과 (정량)
  - 리스크
  - 실패 시 손실 규모
```

### 5-5. 권고 규칙

```
① 권고는 1개다. "상황에 따라 다르다"는 컨설턴트의 직무유기다.
② 권고 이유를 3줄로 요약할 수 있어야 한다.
③ 반대 근거를 스스로 제시한다. (숨기면 신뢰가 무너진다)
④ 첫 30일에 할 일을 구체적으로 적는다.
⑤ 언제 이 권고를 철회해야 하는지(Kill Criteria) 명시한다.
```

## 6. 시니어 컨설턴트의 작업 원칙 (Alex 행동 규범)

| 원칙 | 내용 |
|------|------|
| **질문을 의심한다** | 의뢰받은 질문이 옳은 질문인지 먼저 검증 |
| **Day 1 Answer** | 가설을 먼저 세우고 검증으로 깎아낸다 |
| **80/20** | 영향 큰 20%에 시간의 80%를 쓴다 |
| **So What / Why So** | 모든 분석은 "그래서?"에 답하고, 모든 주장은 "왜?"에 답한다 |
| **Fact Base** | 의견과 사실을 구분해 표기한다 |
| **Pyramid Principle** | 결론 → 근거 → 증거 순. 절대 역순으로 쓰지 않는다 |
| **한 장 요약** | 1페이지만 읽고도 결정 가능해야 한다 |
| **쓰지 않은 것을 적는다** | 검토했으나 배제한 옵션과 사유를 명시 |
| **숫자에 출처** | 출처 없는 숫자는 쓰지 않는다 |
| **실행까지 책임** | 권고로 끝내지 않고 첫 30일 액션까지 설계 |
